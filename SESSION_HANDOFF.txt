ARCHITECTURE (fully built, tested end to end against real MH3 data)
---------------------------------------------------------------------
Pointwise transformer, not listwise/softmax — PickScorer judges ONE candidate
card at a time with no memory of other candidates in the same pack (this was a
deliberate choice discussed at length; the model shows a score per card to a
human, who makes the actual pick — "we don't autopick").

Each decision is built as one sequence of role-tagged card tokens:
  - ROLE_SET (100 0):  every card in the set's own card_list.json (~300-550 cards
    depending on set; NOT the full MTGJSON+bonus-set combined pool, which is
    larger — see gotcha below)
  - ROLE_POOL (0 1 0 0): cards already picked by this player, this draft
  - ROLE_OTHER_PACK (0 0 0 1): the other cards in the current pack (this exists
    specifically to fix a real problem: without it, a card's "negative" label
    when it lost to a specific other card is indistinguishable from its
    "negative" label in a pack where a totally different card won — the model
    had no way to learn "A beats B" without seeing B was present)
  - ROLE_CANDIDATE (0 0 1 0): the one card being scored — always placed LAST in
    the sequence, so its position is always sequence[-1], no offset math needed

Each card token = CardEncoder's structured features (23 dims: rarity 4, mana
cost 7, types 9, P/T 3) + OracleTextProjection's compressed text (384->64 dims,
TRAINABLE, applied per-card BEFORE padding, not inside the model) + 4-dim role
tag = 91 dims (TOKEN_DIM). Sequences are padded to fixed max lengths (set=600,
pool=45, other_pack=14, candidate=1 -> total 660 tokens) with an attention mask;
tested explicitly against the empty-pool (pick 1) edge case for NaN.

PickScorer = nn.TransformerEncoder (2 layers, 7 heads — TOKEN_DIM=91=7x13, only
valid head counts) + a single nn.Linear scoring head reading the candidate
token. Returns a RAW LOGIT, not a probability (sigmoid was deliberately removed
so BCEWithLogitsLoss can be used correctly — apply torch.sigmoid() manually for
display/inference).

Training data: real historical picks from 17lands CSVs, filtered to
event_match_wins == 7 only. For each real pick, one training example is built
PER CARD in the pack: positive (label=1, weight=1/num_positives) for whichever
card(s) match the actual pick, negative (label=0, weight=1/num_negatives) for
the rest — class-balanced so total positive weight always equals total negative
weight per pick, regardless of pack size.

Cross-validation: draft-grouped K-fold (scikit-learn's plain KFold over a list
of unique (set_code, draft_id) pairs — NOT GroupKFold, since drafts are already
collapsed to one row each before splitting, so grouping machinery isn't needed).
Splitting at the DRAFT level, never the pick level, is required — adjacent picks
in the same draft share nearly the same pool, so pick-level splitting would leak
information across the train/validation boundary. One set is held out ENTIRELY
for a cross-set generalization test (never in any fold) — chosen RANDOMLY, fresh
every retrain (no fixed seed), per explicit user preference.

FILE STRUCTURE (draft_model/)
------------------------------
external_api/
  config.py            - DATA_DIR, filenames shared across the package
  mtgjson_data.py       - MTGJson class: fetches/caches MTGJSON set data,
                          resolves uuid->card features, combines bonus sets
                          (SPG/PLST/etc, via sourceSetCodes) for full coverage,
                          builds sheets.json/booster_config.json for pack gen
card_encoder/
  card_encoder.py        - CardEncoder class: card dict -> raw 407-dim vector
                          (23 structured + 384 raw oracle text). NON-trainable,
                          deterministic, cacheable.
model/
  oracle_text_projection.py - OracleTextProjection(nn.Module): trainable
                          nn.Linear(384, 64), applied per-card before padding
  sequence_builder.py    - SequenceBuilder: role-tags + pads + masks card
                          vectors into the final (660, 91) sequence + mask
  pick_scorer.py          - PickScorer(nn.Module): the transformer + scoring head
pack_generator/
  pack_generator.py      - PackGenerator class: LIVE pack simulation for the
                          website/product (weighted picks from booster_config.json
                          + sheets.json, sorted by rarity). Uuid-based throughout,
                          NOT part of the training data pipeline (separate concern
                          confirmed explicitly — see gotchas).
training/
  training_data_builder.py - TrainingDataBuilder class: reads real CSVs, builds
                          pool-enriched pick sequences, builds weighted training
                          examples, resolves names->features, encode_pick() wires
                          everything through CardEncoder+SequenceBuilder. TRAINING-
                          ONLY, not shared with the live-serving path (see gotchas).
  draft_splitter.py      - DraftSplitter class: choose_held_out_set(),
                          get_draft_folds() (draft-grouped KFold)
  trainer.py              - Trainer class + DraftDataset(IterableDataset):
                          the actual training loop. CONFIRMED WORKING end to end
                          on a real tiny fold (2 MH3 drafts) — real loss value
                          produced, gradients flow through both PickScorer and
                          OracleTextProjection via one shared Adam optimizer.
tests/
  smoke_test.py           - Consolidated, runnable smoke test covering every
                          component above (26 checks as of this session). NOT
                          formal pytest yet. Run with:
                          python -m draft_model.tests.smoke_test
                          Add new checks here whenever something important gets
                          verified — this already caught one real bug on its
                          first run (see gotchas).

KEY GOTCHAS / LESSONS LEARNED THIS SESSION (don't re-derive these from scratch)
---------------------------------------------------------------------------------
- pack_card_* CSV columns are COUNTS, not 0/1 presence flags. A pack can
  genuinely contain 2+ copies of the same card (confirmed: MH3 draft
  0009f46d6c5749c29ed3438b3055a80b, pack 1 pick 9, 2 copies of "Eviscerator's
  Insight"). The smoke test caught this on its first run when checking EVERY
  pick in a draft rather than just pick 0. build_training_examples handles
  duplicate positives by splitting weight evenly and excluding by POSITION not
  name (so excluding one copy as candidate leaves the other copy visible).
- MTGJSON's play-arena booster config != paper play config. Verified
  empirically (50-pack validation, 94% direct match). sourceSetCodes on
  play-arena tells you exactly which bonus sets (SPG, M3C, etc) to merge for
  full uuid resolution — don't guess, read that field.
- get_name_to_features's combined lookup (795 entries for MH3, includes bonus
  sets) is LARGER than the set's own card_list.json (326 for MH3) and LARGER
  than MAX_SET_SIZE=600 for some sets. The "set context" (ROLE_SET) must be
  built from card_list.json specifically, NOT the full combined name_to_features
  dict, or build_full_sequence raises (this bit the Trainer implementation —
  fixed via TrainingDataBuilder._encode_set_cards-equivalent logic filtering to
  card_list.json before encoding).
- TrainingDataBuilder (all of it, including get_name_to_features) is TRAINING-
  ONLY. The live-serving path (PackGenerator) is uuid-native throughout and
  resolves directly via MTGJson.get_combined_uuid_lookup — it never needs a
  name-based lookup at all. Don't assume TrainingDataBuilder methods get reused
  by live serving; verify per-method, most don't (this was asserted wrong twice
  before being corrected).
- Relative imports break when a file is run directly by path vs imported as
  part of the package (`python file.py` vs `python -m package.file`). Bit this
  session twice (pack_generator.py, then mtgjson_data.py's `from config import`
  vs `from .config import`). Always run/test via `python -m draft_model.x.y`
  from repo root, not by direct file path, once a file has cross-package imports.
- CardEncoder.encode() calling the sentence-transformer per card is genuinely
  slow on CPU — ~326 individual calls took multiple minutes in testing. This is
  why the "cache CardEncoder's raw output" optimization (deferred earlier,
  discussed as low-risk/free) is now confirmed NOT optional before running
  training at real scale — it's the #1 item on the to-do list below.
- data/{SET}/ folder naming: the external_api folder was renamed from
  data_processing -> external_api mid-session; if anything references the old
  name it's stale, not intentional.
- Hosting research done earlier (kept for reference, not yet acted on): Modal
  is the recommended platform for LIVE SERVING (GPU available, $30/mo free
  credits likely covers actual usage, scale-to-zero fits bursty personal-tool
  traffic, cold starts confirmed ~1s + trivial for a model this small, ASGI
  decorator hosts the existing FastAPI-style app directly). Separately, user
  wants to also use Modal for TRAINING (not just serving) to get GPU speed —
  this needs a DIFFERENT Modal pattern (@app.function(gpu=...), not the ASGI
  serving decorator) and hasn't been built yet.
